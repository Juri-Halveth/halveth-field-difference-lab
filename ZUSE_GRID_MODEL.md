# Zuse grid question — a bounded software experiment

The [interactive research room](zuse.html) visualizes both declared rules from this note in the browser. It links each historical statement to the source used for that statement and presents Juri Janovski's new code as a separate 2026 contribution.

Konrad Zuse's 1967 article ["Rechnender Raum" (reprinted by *Spektrum der Wissenschaft*)](https://www.spektrum.de/pdf/rechnenderraum-pdf/1030307?file=) discusses how a pulse advancing across four neighbours of a Cartesian grid can acquire preferred directions. We use that historical **question** to test whether a local model's observation depends on the chosen representation. The [Konrad Zuse Internet Archive index](https://zuse.zib.de/pdfs) also lists earlier notes on program storage, cellular automata and the computing space; their titles are metadata, not a specification of this implementation.

The [Deutsches Museum's finding aid for Zuse's papers](https://www.deutsches-museum.de/assets/Forschung/Archiv/Download/Findbuecher_PDF/NL_207_Zuse.pdf) records a 25 February 1956 patent application for a machine calculating over grid-arranged field values (patent no. 1122748, granted 25 January 1962). This is specific historical prior work on grid calculations. The finding aid alone does not establish that its hardware, update rule or output is equivalent to the experiment below.

`experiments/zuse-lattice.js` defines two bounded models of our own. One unit begins at `(0,0)`. In the first rule, each occupied cell passes one quarter of its value north, south, east and west. In the comparison rule, each of the eight adjacent cells receives `1/12` and the source cell retains `1/3`. The state is a map from integer coordinates to values. These deterministic distribution rules conserve total value within floating-point tolerance and have no physical units. The comparison rule is our declared control, not a reconstruction of Zuse's hardware.

Run the checks with `npm test`. After four steps, **both** rules have mass `1` and `E[x²] = E[y²] = 2`. Their joint structure differs: the four-neighbour rule has no mass at `(4,4)`, while the comparison rule does. Their mixed fourth moments `E[x²y²]` are respectively `3` and `13/3`. Thus matching the two coordinate variances does not identify the propagation rule. The four-neighbour frontier reaches radius `4` on an axis and `√8` on a diagonal; the comparison rule can also reach `(4,4)`. Same seed, horizon and per-axis second moment do **not** mean identical maximum step distance or equivalent physics. These tests check only the declared software models.

The second rule now supplies a discriminating software comparison. A stronger comparison would bind an observable to a particular measurement process and choose a threshold before seeing the result. Any comparison with measured physics would additionally require an instrument, units, calibration, competing predictions and uncertainty. This code makes no claim about actual spacetime, gravity, digital particles or an exploitable security defect. Zuse's own [1967 article](https://www.spektrum.de/pdf/rechnenderraum-pdf/1030307?file=) says that his investigations at that stage were carried out on paper and called for further computation; our software probe does not retroactively turn that historical proposal into an empirical result.

## Four-place encounter: a separate synthetic layer

The original two-kernel field comparison remains the control. Its four neighbours are destinations of value, not four agents. `experiments/four-encounters.js` adds a separate bounded software model with four starting roles A-D at distinct positions. Every episode creates new instances with qualified IDs such as `E1/A` and `E2/A`; the repeated role label links comparable positions and learned action feedback, not a claim that both instances are one historical being. The background field at step `t` is always the unchanged comparison kernel's `lazyEightNeighbourPulse(t)`. Sliding backward starts one new episode; past action counts and feedback survive, while the visible route starts again. Completed episodes retain their exact snapshots and decisions in session history; the page outlines the previous episode's positions at the same step. A fixed slider value therefore retains the same field but can show a different entity route after an earlier episode. Repeating the same full slider history from a fresh session reproduces the same outcome. Clearing learned feedback before a second episode restores the first route at the same step, a matched control for learning's effect.

Each model entity uses the current field intensity, occupied positions, currently free neighbouring cells and action feedback for its role label. It scores stay, eight chess-king-like moves, and, where its state permits, a one-time clone into a free neighbour. The score includes field signal, unvisited space, separation, prior feedback and a deterministic preference for less tried actions. A clone is scored as two half-charge positions (parent stays, child occupies the destination) with an explicit split cost and coverage benefit; it does not automatically outrank a move. Starting dispositions derived from the role label break the four-way geometric symmetry; feedback can lower the clone-readiness threshold. No random source is used. There is no programmed clone step: the clone option depends on local signal, readiness, available space and the entity's tracked charge; the same explicit scoring rule then competes it against moves. A clone has its own episode-qualified instance ID (`E1/A.2` etc.) and shares its parent's tracked charge. Each original can clone at most once per episode; a new episode starts new instances with new clone eligibility. Children cannot clone in this bounded version. The total tracked charge begins at 4 and remains 4. This is a model accounting quantity, not physical energy or biological reproduction.

The renderer does not assign a named color to A-D. Each agent derives a preferred hue from its identity, position and accumulated feedback, then selects from a twelve-hue palette, excluding already used hues while free hues remain. This is a transparent algorithmic choice, not an assertion of consciousness or literal freedom. The page shows each ID, hue, position, parent and tracked charge alongside the current decision and candidate count; the code retains per-step candidate scores and previous episodes in memory. A page reload begins a fresh session; there is no persistent cross-device journal. The engine's tests cover initial identities, deterministic replay, field invariance across episodes, route variation after learning with a reset-feedback control, unique occupancy and hues, non-forced cloning, lineage, history and charge accounting. The model does not show physical spacetime, actual radicals, radioactive light or a complete account of learning in nature.
